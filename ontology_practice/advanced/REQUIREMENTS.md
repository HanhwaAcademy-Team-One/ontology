# 고급 카페 응용 요구사항

## 목표

온톨로지에 선언한 의미로 메뉴의 재료·성분·공급업체·카페인 분류를 알아내고,
고객 조건과 수량별 재고를 비교해 추천 또는 거절 이유를 제공한다.
주문은 현재 상태에서 다시 검사한 뒤 재고와 주문 정보를 함께 저장한다.

## 기능 요구사항

| ID | 요구사항 | 완료 기준 |
|---|---|---|
| FR-01 | 스키마와 사실을 분리한다 | `ontology.ttl`과 `sample_data.ttl`이 별도 파일이다 |
| FR-02 | 입력을 검사한다 | 필수값 누락, 음수 재고, 중복 매장/재료 재고를 거절한다 |
| FR-03 | 속성 체인으로 재료를 추론한다 | 메뉴→레시피→요구량→재료에서 `containsIngredient`를 얻는다 |
| FR-04 | 성분 및 공급망을 전파한다 | 메뉴의 `containsAllergen`, `menuSuppliedBy`가 추론된다 |
| FR-05 | 조건으로 클래스를 분류한다 | 카페인 값에서 재료와 메뉴의 카페인 클래스가 추론된다 |
| FR-06 | 추천 이유를 설명한다 | 예산·제외 성분·식단·카페인·재고의 모든 불일치 이유를 반환한다 |
| FR-07 | 주문 수량을 계산한다 | 수량에 따라 총가격과 재료 사용량이 함께 증가한다 |
| FR-08 | 같은 재료 사용량을 합산한다 | 레시피에 같은 재료가 두 번 등장하면 합산하여 검사한다 |
| FR-09 | 주문 시 최신 재고를 확인한다 | 잠금 안에서 상태를 다시 읽고 추천 조건을 재검사한다 |
| FR-10 | 주문과 재고를 함께 저장한다 | 성공 후 주문 ID·수량·단가·총액·시각과 재고가 저장된다 |
| FR-11 | 거절된 주문은 상태를 보존한다 | 기존 파일 바이트와 재고가 바뀌지 않는다 |
| FR-12 | 공급업체 영향을 조회한다 | 해당 공급업체의 재료를 사용하는 메뉴와 재료를 반환한다 |
| FR-13 | 재실행 시 상태를 복원한다 | 다음 추천/주문이 저장된 재고와 주문을 읽는다 |
| FR-14 | 학습 샘플을 보존한다 | 주문은 `outputs/`에 기록하고 원본 TTL을 변경하지 않는다 |

## 데이터 요구사항

- IRI를 개체 식별자로 사용하고 표시 이름은 `rdfs:label`로 분리한다.
- 가격은 0 이상 정수 원, 재료량은 양수 `xsd:decimal` g, 재고는 0 이상 decimal g이다.
- 고객은 예산, 카페인 회피 여부, 식물성 재료 조건을 반드시 가진다.
- 재료는 식단 값, 카페인 값, 완성 여부, 공급업체가 있어야 한다.
- 완성된 프로필만 추천에 사용할 수 있다. 성분 목록의 실제 정확성은 입력자의 책임이다.
- 메뉴에는 레시피 하나, 레시피에는 요구량 노드 하나 이상이 필요하다.
- 재고 레코드는 매장/재료 조합별 최대 하나다. 레코드가 없으면 재고 0으로 처리한다.
- 주문 한 건은 메뉴 종류 하나와 수량을 가진다. 고객 예산은 해당 주문 전체의 한도다.

## 기술 요구사항

- Python 3.12+, RDFLib, OWL-RL, pySHACL을 사용한다.
- 로컬 실행과 테스트에는 외부 API 키나 네트워크 호출이 필요하지 않다.
- SPARQL 사용자 선택값은 `initBindings`로 전달한다.
- 일반 추론 결과와 스키마는 상태 파일에 저장하지 않고, 사실과 변경 상태만 저장한다.
- 저장은 같은 디렉터리의 임시 파일을 원자적으로 교체한다.
- 같은 상태 파일의 동시 주문은 독점 잠금으로 막고, 잠금 획득 실패는 재시도 메시지로 반환한다.
- 실패한 명령은 종료 코드 2와 오류 이유를 반환한다.

## 완료 확인 시나리오

1. 샘플 민수에게 아메리카노와 귀리 라테만 조건 일치 결과가 나온다.
2. 샘플 지수의 아메리카노는 카페인 조건으로 제외된다.
3. 두 잔 주문 조건에서 귀리 라테에 필요한 귀리 음료가 400g으로 계산된다.
4. 귀리 라테 한 잔 주문 후 원두 62g, 귀리 음료 100g이 저장된다.
5. 같은 주문을 다시 시도하면 재고 부족으로 거절되며 파일이 바뀌지 않는다.
6. 우유 라테는 민수의 제외 성분/식단 조건 때문에 주문되지 않는다.
7. 프로필 누락, 음수 재고, 중복 재고 입력은 추론 전에 SHACL 검사를 실패한다.
8. 원두 공급업체의 영향 메뉴는 아메리카노·귀리 라테·우유 라테다.

## 범위 밖

실제 건강 판단, 결제, 배송, 복수 메뉴 장바구니, 주문 취소/환불, 분산 잠금,
사용자 인증, 날짜별 재료 유효기간과 교차오염 모델은 구현하지 않는다.
